# WARP Unblock

Портативный Windows x64 клиент: mihomo держит WireGuard-тоннель WARP, нативное приложение на Rust + egui управляет подключением. По умолчанию трафик идёт через **DIRECT**; сервисы из правил — через WARP.

## Установка

Скачайте архив `WarpUnblock-vX.Y.Z-win-x64.zip` из [Releases](../../releases), распакуйте в любую папку (не в Program Files) и запустите `WarpUnblock.exe`.

## Маршруты

Без селекторов и подгрупп: всё, что не попало в правила, идёт **DIRECT**; YouTube, Discord, Telegram, Spotify, мессенджеры, нейросети и списки заблокированных — сразу в **WARP**. Российские домены/адреса и локальная сеть — напрямую. Список в обход редактируется в `app/config/lists/proxy-domains.txt`.

## Запуск

Откройте **WarpUnblock.exe** в корне и разрешите права администратора. Отключите TUN других VPN-клиентов перед подключением.

- **Подключить** — проверить компоненты и конфиг, подготовить профиль, включить TUN и проверить WARP.
- **Остановить** — остановить только процессы этого приложения.
- **Проверить** — проверить файлы, а при активном подключении ещё WARP и API Discord.
- **Тест профиля** — проверить выбранный профиль без TUN.
- **Подобрать автоматически** — проверить профили до первого рабочего и сохранить выбор. Кнопка «Остановить» отменяет подбор.

При закрытии окна активное подключение останавливается. При аварийном завершении дочерние процессы завершаются Windows Job Object. Приложение не устанавливает службу и не прописывает автозапуск.

## Файлы

| Папка          | Содержимое                                                                        |
| -------------- | --------------------------------------------------------------------------------- |
| `app/bin/`     | mihomo, wgcf, самосборный winws и необходимые библиотеки                          |
| `app/config/`  | правила маршрутизации, профили WARP и списки доменов                              |
| `app/scripts/` | внутренняя установка зависимостей и регистрация WARP; приложение вызывает их само |
| `data/`        | локальные настройки, ключи WARP, кеш и логи; полностью исключена из Git           |
| `source/`      | исходный код Rust, Cargo.toml и Cargo.lock                                        |
| `tools/`       | сборка приложения и winws; временные инструменты в `.cache/`                      |
| `docs/`        | инструкции и заметки о текущем состоянии                                          |

Домены для обхода: `app/config/lists/proxy-domains.txt`; напрямую: `direct-domains.txt`. Формат `+.example.com` включает поддомены.

## Профили WARP

Каталог `app/config/strategies.json` содержит 21 профиль. Меняются только UDP-порт WARP, его эндпоинт, количество/размер мусорных пакетов перед handshake и UDP fake в winws. Готовых стратегий обхода отдельных сайтов здесь нет.

Профили — кандидаты, а не обещание работы у любого провайдера. Автоподбор проверяет HTTPS через тоннель на свежем экземпляре WireGuard; результат сохраняется в `data/strategy-results.json`. Перебор не измеряет качество голосовой связи, поэтому Discord-голос проверяется отдельно. Если WARP работает без zapret, его можно не запускать.

Только при первой регистрации аккаунта дополнительно применяется TCP-обход для API Cloudflare. Он завершается после регистрации и не перехватывает сайты.

## Диагностика

Логи находятся в `data/logs/`; их можно открыть из окна. Логи сохраняются после отключения. `launcher.log` — действия приложения, `mihomo.log` — подключения, `zapret.log` — winws, `profile.log` — подготовка WARP. Логи могут содержать домены и IP; ключи находятся в `data/warp/` и `data/mihomo/warp.yaml` — не публикуйте эти файлы.

## Сборка

Приложение: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1`. Нужны Rust 1.95 с rustfmt и MSVC Build Tools. Можно выбрать другую установленную версию через `-Toolchain`; текущий EXE собран Rust 1.93, форматирование проверено rustfmt 1.95. Зависимости зафиксированы в Cargo.lock.

Только winws из исходников: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-winws.ps1 -InstallToolchain`. Это скачает Cygwin/GCC внутрь `tools/.cache/`, без записи в реестр и ярлыков. Повторная сборка: та же команда без `-InstallToolchain`.

Код zapret закреплён на `v72.13`, commit `87e058624c72863db53bdaf7fb6f16576dddb6ab`. Код winws и ресурс manifest компилируются локально; готовые upstream `.o` ресурсы не используются. Библиотека импорта WinDivert остаётся из исходного дерева zapret. SHA-256 и версия GCC — в `app/bin/zapret/winws-build.json`. Вместе с winws копируется соответствующий runtime Cygwin. WinDivert.dll и подписанный драйвер WinDivert64.sys не пересобираются.

# Как это устроено

Проект сделан ради интереса, без гарантий. Этот файл — карта для тех, кто хочет разобраться или поправить.

## Структура репозитория

Монорепо: одна ветка `main`, у каждой платформы своя папка, свой CI и свои теги.

| Папка | Что | CI | Теги |
| --- | --- | --- | --- |
| `windows/` | Rust-приложение (`source/`), ядра и конфиги (`app/`), скрипты сборки (`tools/`) | `.github/workflows/windows.yml` | общий `v*` |
| `android/` | Kotlin + Compose, Gradle-проект | `.github/workflows/android.yml` | общий `v*` |
| `docs/` | Общая документация, формат списков доменов (`DOMAIN-LISTS.md`) | — | — |

CI платформы запускается на push/PR только при изменениях в её папке. Релиз — один на обе платформы: тег `vX.Y.Z` запускает `.github/workflows/release.yml`, он вызывает оба воркфлоу и публикует ZIP, два APK и общий `SHA256SUMS.txt`. Версия одна; Android `versionCode` = major·10000 + minor·100 + patch. Старые теги `android-v*` остались в истории, апдейтер Android их тоже понимает. Дальше в этом файле — Windows; пути указаны относительно `windows/`. Устройство Android — [android/README.md](../android/README.md).

## Общая схема (Windows)

```
WarpUnblock.exe (Rust, GPUI + gpui-component)
 ├─ opera-proxy    — AI HTTPS через Opera EU; транспорт до Opera идёт через WARP
 ├─ winws (zapret)  — маскирует только handshake WireGuard до WARP (UDP)
 ├─ mihomo          — держит WireGuard-тоннель до Cloudflare WARP и TUN, режет трафик по правилам
 └─ wgcf            — регистрирует аккаунт WARP (один раз), ключи лежат в data/
```

- По умолчанию трафик идёт **DIRECT**. В **WARP** уходит только то, что попало в правила: YouTube, Discord, Telegram, Spotify, мессенджеры, нейросети, списки заблокированных и свой список `app/config/lists/proxy-domains.txt`. Российские домены и адреса и локальная сеть — напрямую.
- Правила без селекторов и подгрупп. Единственная группа `WARP` типа `fallback` нужна только потому, что mihomo не умеет направлять правила прямо в прокси из провайдера. Выбирать в ней нечего.
- WARP-профиль (`data/mihomo/warp.yaml`) генерирует `app/scripts/warp.ps1` из аккаунта wgcf. Файл содержит приватный ключ и в Git не попадает.

## Исходники (`source/src/`)

| Файл | Что внутри |
| --- | --- |
| `main.rs` | Запуск, повышение прав (UAC), одиночный экземпляр, флаги `--tray` и `--self-test` |
| `engine.rs` | Рабочий поток: команды `Start / Test / Auto / Check / Stop / Shutdown`, события для UI, проверка здоровья WARP каждые 30 секунд, настройки (`data/settings.json`) |
| `features.rs` | Редактор и нормализация доменов, GitHub Releases, HTTPS-проверки, резервные копии/QR и статистика профилей |
| `opera.rs` | Параметры Opera EU и проверка страны выхода |
| `strategies.rs` | Каталог из 21 профиля доставки WireGuard к WARP (`app/config/strategies.json`) |
| `platform.rs` | WinAPI: Job Object, запуск процессов, задача планировщика для автозапуска, показ/скрытие окна |
| `tray.rs` | Иконка в трее и меню, работает независимо от отрисовки окна |
| `ui.rs` | Интерфейс на GPUI: боковая навигация, страницы «Подключение», «Профили», «Списки», «Настройки», «Журнал», модальные окна (обновление, QR, закрытие), Ренат-мод |
| `update.rs` | Проверка релизов GitHub, загрузка ZIP, сверка SHA-256, замена файлов и перезапуск |

## Профили WARP

Каталог — `app/config/strategies.json`, общий для Windows и Android (Android копирует его при сборке и берёт профили без поля `zapret`). Профиль: эндпоинт WARP, порт, мусорные пакеты AmneziaWG (`jc`, `jmin`, `jmax`) и необязательный `zapret` — ключи `--dpi-desync…` для winws, `{zapret}` подставляется как `app/bin/zapret`. Обвязку (только UDP-порт профиля и IP из `warp-ips.txt`) код добавляет сам, посторонние ключи отклоняются. При смене каталога статистика и выбор профиля сбрасываются (`data/catalog-id.txt`; на Android — отпечаток в настройках).

Регистрация аккаунта: сначала напрямую, затем способы из общего `app/config/registration.json` — у каждого вариант `winws` (TCP 443 только к доменам `warp-hosts.txt`) и/или `byedpi` (Android, локальный SOCKS только для запроса регистрации). `--self-test` прогоняет `winws --dry-run` по всем профилям и способам регистрации.

Проверка профиля: сначала ожидание API mihomo (до 3 с), затем бюджет на ответ WARP: при подборе 1,5 с (на медленной сети до 2,5× лучшей средней задержки, максимум 5 с), при подключении и «Тесте профиля» 5 с — одна попытка рукопожатия WireGuard. При подборе профиль WireGuard пишется без PowerShell, `mihomo -t` — один раз.

Профили меняют только то, как WireGuard доезжает до WARP: UDP-порт и эндпоинт, количество и размер мусорных пакетов перед handshake (AmneziaWG: только `Jc/Jmin/Jmax`), UDP fake в winws. Стратегий обхода отдельных сайтов здесь нет — всё остальное идёт уже внутри тоннеля.

**Автоподбор** запускает свежий экземпляр mihomo без TUN на каждый профиль, останавливается на первом рабочем и сохраняет выбор. Результаты — в `data/strategy-results.json`, из него интерфейс рисует точки в списке профилей. «Рабочий» значит «WARP ответил по HTTPS», а не «голос в Discord хороший».

## Процессы и безопасность

- Все дочерние процессы создаются приостановленными, помещаются в Windows Job Object и только потом запускаются. При закрытии или падении приложения Windows завершает их сама. Чужие VPN приложение не трогает.
- Opera слушает `1371`, принудительный HTTP транспорт WARP — `17892`. Локальные порты: API mihomo `9090` (тест `9091`), прокси `5630` (тест `5631`; не 7890 — его часто держат FlClash и другие клиенты Clash). Несколько экземпляров с одним ключом WARP запускать нельзя.
- mihomo разрешено читать только `app/config/lists` (через `SAFE_PATHS`).
- winws ограничен IP-адресами WARP и выбранным UDP-портом. TCP-обход применяется только один раз, при регистрации аккаунта, и закрывается сразу после неё.
- Служб и записей в реестр нет. Автозапуск — опциональная задача планировщика `WarpUnblock` (при входе, наивысшие права, без UAC-запроса). Выключается тумблером в настройках.

## Трей и закрытие

Крестик по умолчанию сворачивает окно в трей (тумблер в «Настройках»). Показ и скрытие окна делаются штатными вызовами WinAPI (поиск окна по заголовку «WARP Unblock»). Опрос движка — таймер GPUI на главном потоке, он работает и при скрытом окне. «Выход» в трее ставит флаг, таймер его подхватывает и закрывает приложение. Запуск с `--tray` стартует скрытым и сразу подключается; повторный запуск exe показывает уже работающее окно.

## Сборка

Нужны Rust 1.95+ (GPUI использует свежие API std) и MSVC Build Tools (Windows x64):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1
```

Скрипт гоняет `cargo fmt --check`, тесты и релизную сборку. Только winws из исходников (Cygwin/GCC внутри `tools/.cache/`): `tools/build-winws.ps1`.

С Linux можно проверять типы под Windows: `cargo check --target x86_64-pc-windows-gnu` (нужен `gcc-mingw-w64-x86-64`). Это не запускает приложение — ничего из WinAPI там не выполняется.

## Релизы

`.github/workflows/windows.yml` собирает exe на `windows-latest`; при вызове из `release.yml` упаковывает `WarpUnblock-<версия>-win-x64.zip`: в корне `README.md` и папка `WarpUnblock/` (exe и `app/`, лицензии — в `app/licenses/`), рядом `.sha256`. Релиз запускается пушем тега `v*` или вручную в Actions (Release, поле версии).

## Оформление

- Своя плашка окна (системный заголовок прозрачный): перетаскивание, двойной клик, Snap и кнопки окна идут через `WindowControlArea`. Заголовок окна остаётся «WARP Unblock» — по нему трей находит окно (`FindWindowW`).
- Тема: `settings.theme` = `system` (следует за Windows, опрашивается таймером), `light` или `dark`. Цвета заданы константами тёмной темы, `c()` подменяет их парой для светлой.
- Шрифт Manrope вшит в exe (`windows/source/assets/fonts/`, статические начертания из вариативного файла Google Fonts).
- Иконки: `windows/tools/make-icons.py` рисует `app.ico` (ресурс exe через `build.rs`), `app.png` (окно) и `tray-mask.png` (трей красит маску в цвет состояния). Lucide-иконки интерфейса, которых нет в базовом наборе gpui-kit, перечислены в `icon_assets!` в `ui.rs`.
- Светящаяся сетка за главной карточкой (`glow.rs`, на Android — `GlowBackdrop`/`GlowGrid` в `Components.kt`): простой — плывущие пятна, подключение — волны в случайном направлении с золотым гребнем и мерцающим хвостом, подключено — ровное свечение со «звёздами», ошибка — красные пятна. Под клетками мягкое свечение из размытых теней (`paint_drop_shadows`). В светлой теме неподвижная сетка серая, волны без WARN, гребень насыщеннее, а не светлее. Неподвижная часть запекается в картинку один раз на размер и цвет, каждый кадр рисуются только живые клетки; кадры ~30/с и только пока главная открыта и окно активно. Замер в release (v0.7.3+, окно активно, главная): 3–3,6% одного ядра во всех состояниях; свёрнутое окно ~1%. Бесконечные `with_animation(...).repeat()` не использовать: GPUI тогда перерисовывает окно с частотой монитора и в фоне (пульс кнопки при подключении стоил ~13% ядра) — анимации считать от часов в `render`, кадры даёт таймер `tick`. В фоне `tick` перерисовывает окно только при событиях движка и раз в секунду.
- `--preview` + `WARP_PREVIEW_STATE=busy|on|error` показывает интерфейс в этом состоянии (для проверки анимаций без подключения), `cycle` — по кругу каждые 3 с (для переходов).
- Всплывающие уведомления — итог подключения, проверок, сохранений; неактивные кнопки объясняют причину во всплывающей подсказке.

## Обновление

При запуске (тумблер в «Настройках») и по кнопке приложение ищет самый свежий стабильный `v*` с архивом `*-win-x64.zip` и файлом `.sha256`. Окно показывает описание релиза и кнопки «Обновить / Позже / Пропустить версию / Что нового». Установка: соединение останавливается, архив скачивается в `data/update/`, сверяется SHA-256 (без контрольной суммы установка отменяется), распаковывается. Каждый файл заменяется так: старый переименовывается в `*.old` (так можно и с запущенным exe), новый ставится на место; при ошибке всё откатывается. Не трогаются `data/` и три пользовательских списка доменов. Затем запускается новая версия с `--after-update` — она ждёт, пока старая отпустит mutex. Файлы `*.old` удаляются при следующем запуске.

Живая проверка загрузки и SHA-256 на опубликованном релизе: `cargo test -- --ignored live_release_download`.

## Не проверено вживую

Часть функций проверена только компиляцией и скриншотами заглушки интерфейса на Linux: трей и скрытый старт, автозапуск через планировщик, Ренат-мод, прогресс автоподбора. Полный TUN-тест, Discord (включая голос) и YouTube нужно смотреть руками. Если что-то не работает — логи в `data/logs/` (`launcher.log`, `mihomo.log`, `zapret.log`, `profile.log`); они могут содержать домены и IP, ключи в `data/` публиковать нельзя.

## Дополнения v0.5.0

`features.rs` выполняет сетевые запросы и файловые диалоги в фоновых потоках. Импорт разрешает только фиксированные имена списков и файлов аккаунта, проверяет ключи/адреса wgcf, сохраняет предыдущее состояние и откатывает изменённые файлы при ошибке записи. Генерируемый провайдер удаляется после импорта и создаётся заново при подключении. Автозапуск не переносится между компьютерами.

`Command::Best` сравнивает весь каталог без TUN. `Command::Auto` сохраняет прежнее поведение первого успеха. Отменённая попытка не портит статистику, при сравнении выбирается только профиль, прошедший текущую проверку. Общий формат описан в `DOMAIN-LISTS.md`.

Версия для проверки обновлений берётся из `WARP_VERSION` при релизной сборке, иначе из Cargo.toml. Запросы фильтруют стабильные `v*` отдельно от `android-v*`, сравнивают числовые компоненты версий и обрабатывают страницы API. Токены GitHub в приложение не встраиваются.

`tools/prune-releases.ps1` по умолчанию только печатает план. `-PrepareBackups` сохраняет файлы, метаданные и проверяет хеши в `dist/release-backups/`; `-Apply` после подготовки удаляет старые релизы. По одному свежему стабильному релизу каждой платформы и все git-теги сохраняются.

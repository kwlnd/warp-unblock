## Структура и релизы

- Монорепо: только ветка `main`, папки `windows/`, `android/`, `tools/` (генератор иконок, стенд стратегий), `branding/` (SVG знака «!W» — исходник иконок).
- Релиз один на обе платформы: тег `vX.Y.Z` → `release.yml` вызывает `windows.yml` и `android.yml`, публикует ZIP (+ `.zip.sha256` для старых клиентов), APK `arm64-v8a` и `universal`, `SHA256SUMS.txt` и подпись `SHA256SUMS.txt.sig`. Версия общая: `windows/source/Cargo.toml` (+ `Cargo.lock`) и `android/app/build.gradle.kts`; README номеров версий не содержат (ссылки на releases/latest). «Что нового» дописывается к релизу вручную после CI. Старые релизы не удалять.
- Последний релиз — **v0.7.7** (11.11). По версиям: v0.7.2 свечение и переходы; v0.7.3 прокси 7890→5630 (FlClash); v0.7.4 автопереключение, CPU, работа в фоне на Xiaomi, новые адреса; v0.7.5 пул адресов; v0.7.6 иконка «!W», подписанные обновления, обновление через WARP, APK universal, новые README; v0.7.7 фикс подбора на свежей Windows-установке.
- Архив Windows: в корне `README.md` (= `windows/README.md`) и папка `WarpUnblock/` (exe + `app/`, лицензии в `app/licenses/`).

## Windows (GPUI)

- `gpui-kit` 0.9.1, Rust ≥ 1.95 (`cargo +1.95.0`). Своя плашка окна, меню слева, Manrope, светлая/тёмная тема, светящаяся сетка `glow.rs` с плавными переходами между состояниями, знак «!W» в шапке и трее красится по состоянию (серый/жёлтый/оранжевый/красный).
- Нагрузка (release, главная): 3–3,6% одного ядра во всех состояниях, свёрнутое окно ~1%. Бесконечные `with_animation(...).repeat()` не использовать — перерисовывают окно с частотой монитора (было 13–16% при подключении).
- Обновление (`update.rs`): подпись `SHA256SUMS.txt.sig` → SHA-256 архива из подписанного списка → замена через `*.old` с откатом → перезапуск. Полная установка проверена вживую (v0.7.3 → v0.7.4, v0.7.5 → v0.7.6).
- Профиль WARP: нет аккаунта или `wgcf-profile.conf` → `ensure_profile` получает их у API Cloudflare напрямую, затем способами обхода из `registration.json`; подбор делает это один раз до перебора.
- Preview: `--preview`, `WARP_PREVIEW_STATE=busy|on|error|cycle`, `WARP_PREVIEW_UPDATE=1`.

## Android

- Compose, общий стиль с Windows; сетка `GlowBackdrop`/`GlowGrid`; иконки — из `tools/make-icons.py` (адаптивная на графите + одноцветный слой, `ic_logo` в шапке, `ic_notify` в шторке с цветом состояния, `ic_tile`).
- Приложение исключено из своего VPN; апдейтер при недоступном GitHub идёт через вход ядра `127.0.0.1:17892` (`warp-input` → WARP).
- «Работа в фоне» (`Background.kt`): запрос исключения из экономии батареи после первого подключения, карточка в настройках, «Автозапуск» на Xiaomi. Причина — MIUI `LockScreenClean` убивает фон при блокировке экрана.
- Локальная сборка `android/tools/build.ps1` (тулчейн в `android/.toolchain/`); рабочий APK с нативными библиотеками собирает только CI.

## Каталог WARP

- `windows/app/config/strategies.json` = `{endpoints: ["ip:порт"…], profiles: [маскировка…]}`: 14 адресов × 12 профилей (на Android 4 без zapret). Выбор = номер профиля + строка адреса.
- Подбор и автопереключение: сначала все адреса текущего профиля (со следующего за сломанным), потом другие профили. Автопереключение — после двух промахов health-check подряд (30 с + 10 с).
- Проверено на телефоне: блок текущего адреса через iptables → тот же профиль на соседнем адресе через ~20–30 с, VPN не падает.
- Разведка (Ростелеком, 11.11): `188.114.96–99.x` и `162.159.195.x` проходят на всех портах; `192.x` через раз; `193.x` только на нестандартных портах; чистый WireGuard не проходит. Туннель держится >12 ч (со слов пользователя).

## Подпись обновлений

- Ed25519: секрет `UPDATE_SIGNING_KEY` в GitHub, бэкап ключа — `.signing/update-signing-key.pem` (в .gitignore; **пользователю перенести в надёжное место** — без ключа новые релизы не примут уже установленные программы). Публичный ключ — константа `UPDATE_KEY` в `update.rs` и `Updater.kt`.
- Подпись каждого релиза после CI проверяется вручную: `openssl pkeyutl -verify -pubin -inkey pub.pem -rawin -in SHA256SUMS.txt -sigfile sig.bin` (pub.pem собирается из `UPDATE_KEY`).

## Решения

- Ренат мод — секретная пасхалка: в релизах, README и changelog не упоминать.
- Отдельный `armeabi-v7a` не публикуем, вместо него `universal`.
- Случайные параметры маскировки не делаем: 4 пакета 40–70 байт — общий публичный конфиг, не наш отпечаток.
- Бот, который выкачивает каждый релиз целиком (по одной копии каждого файла через ~час после публикации), и всплеск клонов 6–7 ноября (167/87 при 74/37 уникальных) — источник неизвестен, оставляем как есть. «Ловушки» для ИИ-анализаторов в релиз не кладём: сканеры сочтут это признаком вредоноса.
- Зеркала релизов: надёжного готового нет; Codeberg/GitLab через CI — в запасе (нужен аккаунт пользователя).

## Гочи

- FlClash и другие клиенты Clash держат 7890 — у нас 5630/5631 и проверка портов перед стартом.
- У пользователя на ПК `D:\Files\WarpUnblock` (рабочая установка; `*.bak` — старые exe и `warp.ps1` от ручной подмены 11.11) и dev-копия в `windows/` (`WarpUnblock-dev.exe`, данные в `windows/data/`).
- Проводник Windows кэширует иконку exe по пути: после обновления может показывать старую — `ie4uinit.exe -show`.
- adb из Git Bash: `export MSYS_NO_PATHCONV=1`. Root-команды на телефоне — через файл-скрипт, а не вложенные кавычки.
- Python-heredoc в Bash: `'\\n'` внутри строки превращается в настоящий перевод строки в файле — экранированные последовательности вставлять инструментом Edit.
- Gradle: параллельные запуски портят инкрементальный кэш Kotlin — `clean`. `git checkout -- файл` при незакоммиченных правках не использовать.
- Счётчики загрузок GitHub обновляются с задержкой в минуты.

## Структура (с 2026-11-10)

- Монорепо: ветка `main`, папки `windows/` и `android/`; потом сюда же ляжет `linux/`. Ветка `android` влита в `android/` с историей (subtree-merge) и больше не нужна. Удалять её с GitHub только с согласия пользователя.
- CI: `.github/workflows/windows.yml` (теги `v*`) и `android.yml` (теги `android-v*`). На push в `main` и в PR запускаются только при изменениях в папке своей платформы. Сборка ветки или PR даёт версию `0.0.0` и ничего не публикует.
- Удалена слитая ветка `ccr-4647c81e-71p6fl`.

## Windows: GPUI + обновления (ветка `monorepo`, ещё не запушена)

- GUI переписан с egui на GPUI (`gpui-kit` 0.9.1 = `gpui-pre` 0.3.12 + `gpui-component`). Нужен **Rust ≥ 1.95** (`std::hint::cold_path`); локально `cargo +1.95.0`, `windows/tools/build.ps1` уже пинит 1.95.0. Из `gpui-component` используется только `Textarea`, остальное — свои элементы в `ui.rs`.
- `update.rs`: окно «Доступна версия» при запуске/по кнопке → скачивание ZIP, SHA-256, замена файлов через `*.old` с откатом, перезапуск `--after-update`. `data/` и три пользовательских списка не трогаются.
- Проверено: 15 unit-тестов, clippy `-D warnings`, fmt, `--preview` вживую (все страницы, редактор списков, окно обновления на сборке `WARP_VERSION=v0.0.1`). Живая загрузка v0.5.1 + SHA-256 + распаковка: `cargo test -- --ignored live_release_download` — ок.
- Не проверено: реальная установка обновления с перезапуском (нужен admin/UAC и релиз на GPUI), трей/скрытый старт на GPUI, Ренат-мод с картинками, подключение WARP/Opera через новый UI.
- Env `WARP_PREVIEW_UPDATE=1` включает проверку обновлений в `--preview` (для демонстрации окна).
